# DualMind: проверка ошибок и правила исправлений

## Подтверждённые факты
- Ветка `maid-base` не обнаружена при проверке GitHub через доступный поиск веток.
- `Mobile-Artificial-Intelligence/maid` содержит `package.json`, `app.config.ts` и лицензию MIT.
- В исходном репозитории Maid отсутствует `android/gradlew`; Android-проект должен генерироваться до Gradle-сборки.
- Доступный интерфейс GitHub не предоставил список запусков Actions или их журналы. Поэтому причины падения workflow пока не установлены.

## Ошибки предыдущих попыток и выводы
1. Нельзя удалять рабочую папку `.git` при импорте: теряется контекст репозитория и подключение к origin. Импорт должен исключать чужую `.git`.
2. Нельзя запускать `./gradlew` до `expo prebuild`, если в исходниках нет Android-проекта.
3. Вложенный YAML в shell-heredoc нужно проверять на отступы; для генерации используется `textwrap.dedent`.
4. Нельзя считать push коммита доказательством, что GitHub Actions успешно отработал.
5. Не следует многократно менять workflow наугад без свежих логов. Сначала проверка run status и stacktrace, затем минимальный патч.

## Следующий диагностический порядок
1. Проверить, включены ли Actions в настройках репозитория и появился ли запуск `Import Maid foundation`.
2. При ошибке получить полный лог конкретного job, исправить первую подтверждённую причину.
3. Подтвердить появление `maid-base` и наличие оригинальной MIT-лицензии.
4. Проверить `Build DualMind Maid Android`, сохранить stacktrace и исправлять только реальные ошибки.
5. Успешным результатом считать загруженный артефакт APK из завершённого зелёного workflow.

Не менять `AlarmGuard`; не публиковать API-ключи; сохранять старую ветку `main` до проверки новой основы.
